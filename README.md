# PQ 공고 자동 수집 시스템 (재구축판)

지자체·공기업·조달청 등 다수 발주처 게시판을 자동으로 순회해 조건에 맞는 공고를
찾아 구글 시트에 쌓고, Streamlit 대시보드에서 검토하는 시스템.

기존 저장소(`main.py` / `main_major.py` / `main_max.py` / `main_pure.py` 4벌)를
분석한 뒤, **단일 엔진 + 자동 단계 상승(escalation) 구조**로 다시 짰다. 자세한
문제 진단은 대화 중 전달한 `project_overview.md`를 참고.

## 폴더 구조

```
app.py                  # Streamlit 대시보드 (UI 전용)
main.py                 # 수집 실행 진입점 (CLI / GitHub Actions / app.py에서 subprocess로 호출)
config.py               # 설정값 + 시크릿 로딩 (하드코딩된 비밀번호/키 없음)
storage.py              # 구글 시트 읽기/쓰기 전담
site_registry.py        # 명부 엑셀 + URL 오버라이드로 '수집 대상 목록' 구성
engine.py               # 사이트별 자동 단계 상승(오케스트레이션) + 병렬 실행
scrapers/
  base.py               # 공통 파싱 로직 (행 파싱, 첨부파일 딥스캔)
  generic_requests.py   # 2순위: requests + BeautifulSoup
  generic_selenium.py   # 3순위: 범용 Selenium
  api_g2b.py            # 1순위: 나라장터 Open API
  custom/
    khnp.py             # 4순위: 한국수력원자력 K-Pro 전용 (팝업닫기→메뉴클릭→대기→클릭)
    igunsul.py           # 4순위: 아이건설넷 로그인 전용
utils/
  logging_setup.py      # 실행 로그 (콘솔 + 구조화된 RUN_LOG, 실패 원인 추적용)
  date_parser.py         # 텍스트 안 날짜 추출
.github/workflows/auto_run.yml   # 수동 실행용 GitHub Actions
.streamlit/secrets.toml.example  # 로컬 개발용 시크릿 템플릿 (실제 값은 커밋 금지)
```

## 이전 구조 대비 무엇이 바뀌었나

1. **엔진 4개 → 1개**: 더 이상 "빠른/정밀/극한/주요4대"를 사람이 고르지 않는다.
   `engine.py`가 사이트별로 `requests → (실패 시) selenium → (그래도 실패 시) 수동확인`
   순서를 자동으로 시도한다. 이전 버전은 대시보드 라디오 버튼 기본값이 Selenium이
   전혀 없는 "빠른 탐색"이라, 별도로 바꾸지 않으면 JS 렌더링이 필요한 사이트가
   전부 조용히 누락됐다 — 이 문제 자체가 구조적으로 사라진다.
2. **KHNP 등 '자체 시스템형' 사이트 전용 처리**: `scrapers/custom/khnp.py`에
   말씀하신 흐름(팝업 닫기 → 입찰공고 메뉴 → 입찰공고조회 → 대기 → 클릭)을
   구현했다. **다만 이 사이트는 봇 방어가 강해 실제 DOM을 확인 못 하고 화면
   캡처만으로 작성했다.** 처음 실행해보면 셀렉터 조정이 필요할 가능성이 높은데,
   실패해도 이제는 `run_log`에 "어느 단계(팝업/메뉴클릭/대기/파싱)에서 막혔는지"가
   정확히 남으므로, 그 로그를 보고 한 부분만 고치면 된다.
3. **침묵의 에러 제거**: `except: pass`를 없애고 `log_failure()` / `log_manual_required()`로
   통일했다. 실행 후 대시보드의 "🚨 수동 확인 필요" 메뉴에서 실패 원인을 바로 볼 수 있다.
4. **자격증명 하드코딩 제거**: 아이건설넷 계정, 조달청 API 키, 대시보드 비밀번호를
   전부 `config.get_secret()`으로 옮겼다 (환경변수 → Streamlit secrets 순으로 탐색).
   **기존에 코드에 평문으로 있던 값들은 git 히스토리에 이미 노출되어 있으니, 여유
   되실 때 실제 비밀번호/키 자체를 교체하시는 걸 권장한다.**
5. **GitHub Actions 워크플로우 수정**: `google_key.json`을 만드는 단계가 아예
   없어서 기존 워크플로우는 실행될 때마다 구글 시트 연결 단계에서 실패하고
   있었다. 이번에 시크릿에서 키 파일을 만드는 단계를 추가했고, 존재하지도 않는
   파일(`verified_sites.json`, `저장된_공고모음.xlsx`)을 커밋하려던 죽은 단계는 제거했다.
6. **실패 원인 시각화**: 신규 구글시트 탭 `run_log`(실패 로그), `manual_check`
   (자동화 포기 목록)를 만들고, 대시보드에 "🚨 수동 확인 필요" 메뉴로 노출했다.

## 배포 전 설정할 것 (필수)

### 1) 구글 시트
기존과 동일하게 `맞춤공고_DB`라는 이름의 구글 스프레드시트를 그대로 쓰면 된다.
아래 탭이 필요하다 (없으면 코드가 자동 생성하는 탭도 있지만, `notices`/`collected_orgs`는
최초 1회 직접 만들어두는 걸 권장):
- `notices` (헤더: 출처, 등록일, 공고제목, 상세링크, notice_key, 등록시각, 특이사항, 검토유무)
- `collected_orgs` (헤더: org_name)
- `url_overrides` (헤더: 발주기관명, 정확한_게시판_URL, 비고) — 없어도 동작함
- `settings`, `run_log`, `manual_check` — 없으면 코드가 자동 생성

### 2) 시크릿 등록
`.streamlit/secrets.toml.example`을 참고해서:
- **Streamlit Cloud**: 앱 Settings → Secrets에 붙여넣기
- **GitHub Actions**: 저장소 Settings → Secrets and variables → Actions에
  `GOOGLE_CREDENTIALS`, `G2B_API_KEY`, `IGUNSUL_ID`, `IGUNSUL_PW` 등록

### 3) 로컬 테스트
```bash
pip install -r requirements.txt --break-system-packages
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # 값 채우기
streamlit run app.py
```

## 최신 업데이트 (전수조사 결과 반영)

실제 84곳 전수조사 로그를 분석한 결과, **59곳(70%)이 '클라우드 IP 차단'으로 실패**했습니다.
차단된 곳들을 계열별로 보면 지방해양수산청·유역환경청·지방국토관리청 등 중앙부처
지방청과 새올 시스템을 쓰는 시/군/구청이 집중적으로 막혀 있고, 공사·공단 계열
(대전도시공사, LH, 국가철도공단 등)은 대체로 잘 됩니다. 개별 사이트가 각자 막는 게
아니라 **정부통합전산센터/새올 시스템처럼 여러 기관이 공유하는 인프라 단위로
클라우드 IP 대역을 차단하고 있는 것으로 보입니다.**

**결론**: README 상단에 적어둔 "국내 IP 우회" 표의 방법 중 하나를 실제로 도입할
시점으로 보입니다. 70%가 막히는 상황에서는 코드 개선만으로는 한계가 있습니다.

이번에 추가로 반영한 것:
1. **불필요한 재시도 제거**: 접속 자체가 막힌 사이트는 requests든 selenium이든 같은
   네트워크 경로로 나가므로 selenium 재시도도 똑같이 막힌다. 이제 requests 단계에서
   '연결 자체 실패'가 확인되면 selenium 재시도를 건너뛴다 (사이트당 30~50초 절약 -
   차단된 사이트가 많을 때 전체 실행 시간이 크게 줄어듦).
2. **연결 타임아웃 단축**: `requests`의 타임아웃을 (연결 5초, 읽기 20초)로 분리.
   접속 자체가 안 되는 경우 20초까지 기다리지 않고 5초 만에 실패 판정.
3. **진행률 표시줄(프로그레스 바) 추가**: "공고 자동수집" 화면에 가로 막대형
   진행률 바가 생겨서, 지금 몇 곳 중 몇 곳을 처리했는지 실시간으로 보인다.
   전수조사처럼 오래 걸리는 작업에서 얼마나 남았는지 보고 기다릴지 판단할 수 있음.



1. **한국수력원자력 바로가기 링크 수정**: `https://khnp.co.kr`(도메인 루트, 안 열림)
   → `https://ebiz.khnp.co.kr/login.do`(실제 K-Pro 로그인 화면)로 수정.
   `config.KNOWN_HARD_SITES`에 `label`/`url`/`reason`을 함께 관리하도록 구조 변경.
2. **"수동 확인 필요" → "🔍 실패 로그 분석"으로 명칭 변경** (사이드바 메뉴, 페이지 제목 등
   화면에 보이는 문구 전체). 내부 구글시트 탭 이름(`manual_check`)은 기존 데이터 연속성을
   위해 그대로 유지.
3. **"발주처 URL 관리" 화면을 목록 선택 방식으로 전면 개편**:
   - 기존에는 스프레드시트 형태로 발주기관명을 직접 타이핑해야 했음
   - 이제는 "✏️ 등록된 발주처 수정" 탭에서 명부에 등록된 전체 발주처 이름을
     드롭다운으로 골라서 그 발주처의 URL만 수정/삭제할 수 있음
   - "➕ 새 발주처 추가" 탭에서 명부에 아예 없는 새 발주처를 이름+URL로 추가하면,
     **엑셀이나 코드를 건드리지 않고도** 다음 수집부터 바로 대상에 포함됨
     (`site_registry.py`가 오버라이드 중 기존 명부에 없는 항목을 자동으로 새
     발주처로 추가하도록 수정됨)

## 페이지네이션(다음 페이지) 지원 추가 — 적응형 중지 조건

유성구청 도시계획과처럼 하루에 10건 넘게 올리는 게시판에서 실제로 확인된 문제:
1페이지만 읽다 보니, 다음 수집 사이에 새 공고가 쌓이면 어제 공고가 2페이지로
밀려나서 **영원히 누락**되는 현상이 있었다 (2026-08-26자 "건설공사 안전점검
수행기관 지정 공고[원신흥동 557-1]"가 정확히 이 케이스였음 - 하루 평균 5~13건씩
올라오는 게시판에서 해당 날짜만 0건으로 완전히 비어 있었다).

처음에는 "무조건 2페이지 더 본다"는 고정 방식으로 고쳤는데, 사용자 피드백으로
더 나은 방식으로 재설계했다: **페이지를 고정된 개수만큼 보는 게 아니라, 이미
저장해둔 공고(notice_key가 history에 있음)나 수집 기간보다 오래된 공고를
만날 때까지 계속 다음 페이지로 넘어간다** (`scrapers/base.py`의
`page_has_stop_signal` / `find_next_page_url`). 게시판은 보통 최신순 정렬이므로,
이미 아는 지점을 만나면 그 아래는 다 예전에 이미 본 내용이라고 보고 멈춘다.

- 하루 5건 올리는 게시판: 1페이지에서 바로 멈춤 (예전과 동일하게 빠름)
- 하루 20건 올리는 게시판: 필요한 만큼(3페이지든 5페이지든) 알아서 더 감
- `config.MAX_PAGINATION_SAFETY_CAP`(기본 8페이지)은 혹시 모를 오작동으로 인한
  무한 루프만 막는 안전장치이고, 정상적인 경우 대부분 1~2페이지에서 멈춘다.

실제 유성구청 사례(8/27 신규 2건 + 8/26 신규 1건 + 8/22 기존 공고를 만나서 중단)를
그대로 재현해 정확히 그 지점까지만 가고 3페이지는 안 가는 것까지 테스트로 확인했다.
안전 상한 자체가 제대로 작동하는지(무한 루프 방지)도 별도로 확인함.

**한계**: 페이지 번호가 `<a href="...">` 형태의 실제 링크로 되어 있는 게시판만
지원한다. `href="#"`이고 `onclick`으로만 페이지를 넘기는 게시판은 이 방식으로는
따라갈 수 없다(자바스크립트 실행이 필요해서, 클릭 자동화까지 붙여야 함 - 필요하면
추후 확장 가능).

## 제목 추출 로직 개선 — '공고번호'와 '제목'이 분리된 게시판 대응

아산시처럼 게시판에 '고시공고번호'(예: 아산시 공고 제2026-3026호)와 '제목'(실제
내용을 설명하는 문장)이 서로 다른 칸에 있고, 링크는 번호 쪽에 걸려있는 사이트가
있다. 예전 코드는 `<a>` 태그 하나의 텍스트만 제목으로 썼기 때문에, 이런 사이트에서는
**번호만 저장되고 진짜 제목은 전부 유실되고 있었다** (실제 데이터로 확인: 아산시
73건 전부 "아산시 공고 제2026-XXXX호" 형태였고 실제 제목이 하나도 없었음).

이제 `<a>` 태그 텍스트 하나만 보지 않고, 같은 행의 모든 셀 텍스트를 후보로 모은
뒤 "OO시 (읍면동) 공고/고시 제OOOO호" 형식만 담은 후보는 제외하고, 남은 것 중
가장 긴(=가장 설명적인) 텍스트를 제목으로 고른다(`scrapers/base.py`의
`_pick_title`). 실제 아산시 데이터로 재현 테스트했고, 기존에 잘 되던 사이트
(보령시, 유성구청처럼 `<a>` 자체가 이미 완전한 제목인 경우)도 회귀 없이 그대로
동작하는 것까지 확인했다.

## 나라장터(G2B) 수집 범위 확대

**(중요 수정) 주소 자체가 틀려서 전부 실패하고 있었음**: 실제 실행 로그로 확인해보니
기존 3개 오퍼레이션(원래 되던 것 포함)까지 전부 `NO_OPENAPI_SERVICE_ERROR`로 실패하고
있었다. 원인은 End Point 주소 자체가 잘못됐던 것 - `http://apis.data.go.kr/1230000/
BidPublicInfoService04/...` 를 쓰고 있었는데, 공공데이터포털 '활용신청 상세기능정보'
화면에서 실제 승인받은 주소를 직접 확인해보니 `https://apis.data.go.kr/1230000/ad/
BidPublicInfoService/...` 였다 (04 없음, /ad/ 경로 있음). 오퍼레이션명도 대부분
지어낸 이름이었어서, 화면에 나온 정확한 이름(`getBidPblancListInfoCnstwk`(공사),
`getBidPblancListInfoServc`(용역), `getBidPblancListInfoThng`(물품),
`getBidPblancListInfoFrgcpt`(외자), `getBidPblancListInfoEtc`(기타공고))으로 전부
교체했다. 이제 업무구분 4개 + 기타공고까지 총 5개를 가져온다.

**키워드 필터 제거**: 나라장터 정식 입찰공고 제목은 게시판 공지 제목과 형식이 달라서
("OO 교량 정밀안전진단 용역"처럼 실제 사업명) 게시판용 키워드("모집,안전,공고")가
거의 안 맞았을 가능성이 높다. 사용자 결정에 따라 나라장터는 키워드 필터 없이
전부 수집하도록 변경했다 - 대신 대시보드의 "🌟 주요 4대 중앙 공고" 탭에 자동으로
모이므로(출처에 "(나라장터)"가 붙어서 분류됨), 거기서 검색창으로 원하는 것만 걸러
보면 된다.

**"나라장터만 빠르게" 옵션 추가**: "타겟 발주처 설정"에서 "전수조사"를 끄고
발주처를 고르는 드롭다운에 **"나라장터 (API - 사이트 스캔 없이 바로 조회)"**라는
항목이 추가됐다. 이것만 선택하면 84곳 게시판 스캔을 전부 건너뛰고 나라장터 API만
호출해서 몇 초 안에 결과를 확인할 수 있다 (실제 사이트가 아니라 명부에는 없는
가상의 선택지이고, `config.G2B_VIRTUAL_ORG_NAME`으로 관리된다). 다른 발주처와
같이 선택하면 그 발주처들 + 나라장터가 함께 수집된다.

## 프록시 토글 (무료, 실험적)

"공고 자동수집" 화면에 "🌐 무료 프록시로 우회 시도" 토글이 추가됐다. 켜면 매 실행마다
ProxyScrape의 무료 API(회원가입/키 불필요)에서 한국(KR) IP 프록시 후보를 받아와서,
그중 실제로 살아있는 것 하나를 찾아 이번 실행 동안만 그 프록시로 우회한다.

**작동을 보장하지 않는다는 점을 분명히 밝혀둔다:**
- 여기서 쓰는 건 전부 '무료 공개 프록시'다. 진짜 가정집 회선이 아니라 대부분
  데이터센터/오픈릴레이 서버라서, 지금 우리가 막히는 이유(클라우드 IP 차단)와
  똑같은 이유로 이 프록시들도 막힐 수 있다.
- 무료 프록시는 수명이 짧다(몇 분~몇 시간). 어떤 실행에선 잡히고 어떤 실행에선
  하나도 안 잡힐 수 있다. 실행 로그 맨 위 `[프록시]`로 시작하는 줄에서 이번에
  프록시를 찾았는지, 못 찾아서 그냥 진행했는지 바로 확인할 수 있다.
- 대전 지역처럼 확실한 우회가 꼭 필요한 경우, 무료 프록시보다 회사 사무실
  회선에 GitHub Actions 셀프호스팅 러너를 두는 쪽을 권장한다 (아래 참고) —
  그건 '진짜' 대전 IP라서 프록시 뽑기 운에 기대지 않아도 된다.
- **(실제 실행에서 확인된 것) "IP 차단" 로그가 전부 진짜 차단은 아닐 수 있다.**
  프록시를 거치면 클라이언트→프록시→대상 서버로 홉이 하나 늘고, `https://`
  사이트는 프록시와 CONNECT 터널을 먼저 맺어야 하는데 이 단계도 '연결 타임아웃'
  값을 쓴다. 무료 프록시 자체가 느릴 수 있어서, 원래는 됐을 연결을 "차단"으로
  잘못 판정하는 사례가 실제로 있었다 (에러 메시지에 최종 목적지 이름이 나와도
  실제로는 프록시를 거친 시도였음). 그래서 프록시 사용 중에는 연결 타임아웃을
  5초 → 15초로 자동으로 늘리도록 고쳤다(`config.get_request_timeout_tuple()`).
  그래도 실패하면 그때는 정말 차단일 가능성이 높다.

## 대전 지역(중요도 높음)에 대한 별도 권장 사항 → 두 개의 수집 버튼으로 구현됨

셀프호스팅 러너를 설치한 뒤, 대시보드 "공고 자동수집" 화면에 버튼이 두 개로 늘어난다.

- **🚀 지금 바로 수집 (클라우드)**: 예전과 동일하게 Streamlit Cloud에서 바로 실행.
  빠르지만 클라우드 IP를 차단하는 사이트는 여전히 못 잡음.
- **🏢 사무실 PC로 확실하게 수집**: Streamlit이 직접 실행하는 게 아니라, GitHub에게
  "워크플로우 실행해줘"라고 신호만 보낸다. 실제 실행은 대전 사무실 PC(셀프호스팅
  러너)에서 일어나고, 결과는 **똑같은 구글 시트**에 쌓이므로 대시보드 화면은
  완전히 동일하게 쓰면 된다. 다만 실행이 사무실 PC에서 비동기로 일어나기 때문에
  Streamlit 화면에 실시간 로그가 뜨지는 않고, 대신:
  - 버튼 아래 "🏢 사무실 PC(GitHub Actions) 최근 실행 상태"에서 진행 상태(대기중/
    실행중/완료)를 새로고침해서 확인할 수 있고
  - "GitHub Actions에서 실시간 로그 보기" 링크를 누르면 실제 로그를 볼 수 있다.

**필요한 설정**: `.streamlit/secrets.toml.example`의 `GITHUB_TOKEN`(이 저장소에 대한
Fine-grained Personal Access Token, 'Actions: Read and write' 권한)과
`GITHUB_REPO`("owner/repository" 형식)를 Streamlit Secrets에 등록해야 두 번째
버튼이 활성화된다. 등록 안 해도 첫 번째 버튼(클라우드)은 그대로 잘 동작한다.

**중복 실행 방지 개선**: 예전에는 "지금 실행 중인지" 잠금 관리가 Streamlit
버튼 쪽 코드에만 있어서, 클라우드에서 실행 중일 때 GitHub Actions로도 동시에
실행하면 서로 몰랐다. 이번에 잠금 획득/해제 로직을 `main.py` 안으로 옮겨서,
어느 경로로 실행되든(클라우드/사무실 PC) 같은 구글 시트를 통해 서로의 실행
여부를 확인하고 기다리도록 고쳤다.

**참고**: 완전 자동 스케줄(예: 매일 정해진 시간에 자동 실행)은 일부러 넣지
않았다 — 사용자가 실사용 중 "자동 실행은 트래픽이 몰리면 늦게 도는 경우가 있어
수동이 더 낫다"고 판단해, 지금처럼 버튼을 눌러서 원하는 시점에 실행하는 방식을
유지하기로 했다. 나중에 필요해지면 워크플로우 파일에 `schedule:` 트리거를
추가하는 것만으로 쉽게 켤 수 있다.

(참고로 이 기능을 만들게 된 계기: 대전광역시 산하 6곳(중구·대덕구·유성구·서구·
동구청 + 상수도사업본부)이 두 번의 실행 모두에서 꾸준히 클라우드 IP 차단으로
실패한 것이 확인됐고, 회사가 대전 소재라 이 지역 커버리지가 특히 중요했다.
GitHub Actions 셀프호스팅 러너 비용은 퍼블릭 저장소면 완전 무료, 프라이빗
저장소면 2026년 3월부터 분당 $0.002의 아주 저렴한 비용이 든다.)

## 검색 키워드 확장 + 업무 무관 공고 제외 필터

기본 검색 키워드에 "진단", "정밀"을 추가했다 (`모집,안전,공고,진단,정밀`). 또한
실사용 중 확인된, 우리 업무와 거의 무관한(약 99%) 공고 유형을 제목 기준으로
아예 제외하는 `config.EXCLUDE_KEYWORDS` 목록을 추가했다: 공시송달, 무연고,
견적제출공고, 기간제, 분묘개장, 주민등록, 보상계획, 수강생, 합격자, 임용,
모니터링. 이 단어가 제목에 있으면 다른 키워드가 맞아도 무조건 제외된다
(`scrapers/base.py`의 `matches_keywords`/`is_excluded_title`). 나라장터는
포함 키워드 필터가 없지만(사용자 결정), 이 제외 필터는 나라장터에도 동일하게
적용했다 - 업무 무관 판정은 출처와 상관없는 품질 필터이기 때문이다.

## "공고 통계 및 분석" / "게시판 · 메모장" 메뉴 구현

두 메뉴 모두 "추후 확장 예정" 상태의 빈 placeholder였던 것을 실제로 구현했다.

- **공고 통계 및 분석**: 전체 공고 수/고유 발주처 수/검토 상태별 건수 요약,
  발주처별 Top 15 막대그래프, 검토 상태 분포, 등록일 기준 날짜별 추이 꺾은선,
  그리고 이번 명부 기준 "정상 수집 발주처 수" vs "수동확인 필요 발주처 수"
  요약까지 보여준다.
- **게시판 / 메모장**: 팀원 누구나 메모를 작성/조회/삭제할 수 있는 공유 공간.
  `team_notes`라는 새 구글시트 탭에 저장되며(작성자는 선택 입력), 최신순으로
  보여주고 각 메모마다 삭제 버튼이 있다. 삭제는 밀리초 타임스탬프 id로 정확히
  그 한 줄만 찾아서 지우므로, 다른 메모에 영향 없다.

## "자동 제외된 공고" 메뉴 신설 — 제외 = 삭제가 아니라 별도 분류

기존에는 EXCLUDE_KEYWORDS에 걸린 공고를 그냥 조용히 버렸는데(continue로 스킵),
이제는 완전히 버리지 않고 새 구글시트 탭 `excluded_notices`에 저장한 뒤
사이드바 "🚫 자동 제외된 공고" 메뉴에서 훑어볼 수 있게 했다.

이를 위해 스크래퍼들의 반환 형태가 바뀌었다 - `generic_requests.scrape_board()`,
`generic_selenium.scrape_board()`는 `(결과, 발견행수, 네트워크에러)` 3-튜플에서
`(결과, 제외된결과, 발견행수, 네트워크에러)` 4-튜플로, `scrapers/custom/*.py`의
`scrape()`와 `scrapers/api_g2b.py`의 `fetch()`는 `결과 리스트` 하나만 반환하던 것에서
`(결과, 제외된결과)` 튜플을 반환하도록 바뀌었다. `engine.py`가 이걸 모아서
`run_all_sites()`가 `excluded_notices`까지 함께 반환하고, `main.py`가 정상 공고는
`notices` 탭에, 제외된 공고는 `excluded_notices` 탭에 각각 중복 없이 저장한다
(`storage.append_excluded_notices`). 실제 필터링 3종 시나리오(핵심키워드 강제포함
/ 순수 제외 / 게시판+나라장터 혼합)를 재현해 정확히 분리 저장되는 것까지 확인했다.

**주의**: 이 변경으로 여러 파일의 함수 시그니처가 바뀌었으므로, 이 zip은 통째로
교체해야 한다 (일부 파일만 골라서 옮기면 튜플 언패킹 오류가 난다).

## 실행 취소 시 잠금이 안 풀리는 문제 대응

GitHub Actions에서 실행 중 '취소(Cancel)'를 누르면 프로세스가 강제 종료되면서,
잠금을 풀어주는 `finally` 코드가 실행될 틈도 없이 죽어버린다. 그러면 원래
15분 뒤 자동으로 풀리도록 안전장치가 있긴 하지만, 그 15분을 기다려야 다시
실행할 수 있었다. 이제 "현재 다른 실행이 진행 중입니다" 경고 아래에 "혹시
방금 실행을 '취소'하셨나요?" 펼침 메뉴가 생겨서, 그 안의 버튼으로 즉시 잠금을
풀 수 있다 (실제로 다른 곳에서 아직 실행 중일 때 잘못 누르면 두 실행이 겹칠
수 있다는 경고 문구도 함께 표시된다).

## 리퍼러(Referer) 없이 직접 접속하면 막는 사이트 대응

세종도시교통공사 실제 테스트에서 발견: 주소를 직접 열면(주소창에 쳐서 들어가거나
우리 스크래퍼가 바로 요청하면) "처리 중 오류가 발생하였습니다" 안내 페이지로
돌려보내고, 자기 사이트 안에서 메뉴를 눌러 넘어온 경우에만 실제 내용을 보여주는
사이트가 있다 - 주소 자체는 맞는데 "들어간 경로"가 이상하다고 판단해서 막는
전형적인 Referer 체크였다.

`config.get_request_headers(url)`을 새로 만들어서, 요청을 보낼 때마다 그 사이트
자신의 루트 주소(예: `https://www.sctc.kr/`)를 Referer로 채워 보내도록 했다 -
"이 사이트 홈페이지에서 자연스럽게 넘어온 것처럼" 위장하는 셈이다. `requests`
기반 경로(`scrapers/base.py`, `scrapers/generic_requests.py`)뿐 아니라 Selenium
경로(`scrapers/generic_selenium.py`)에도 적용했는데, Selenium은 일반
`driver.get()`으로는 Referer를 지정할 수 없어서 Chrome DevTools Protocol의
`Page.navigate`를 대신 사용했다(`_navigate_with_referer`, CDP 실패 시 기존
`driver.get()`으로 안전하게 대체됨). 이건 세종교통공사만이 아니라 비슷한 방식의
Referer 체크를 쓰는 다른 사이트에도 도움이 될 수 있는 공통 개선이다.

## 사무실 PC(Windows) 실행 시 한글이 깨지는 문제 대응

**실제 실행 로그로 확인된 심각한 문제**: "인천국제공항공사,대전광역시 동구청(건축과),
대전광역시 동구청(일자리경제과)" 3곳만 골라서 돌렸는데 12초 만에 끝나고 아무것도
안 잡혔다. 로그에 `UnicodeEncodeError: 'cp949' codec can't encode character`가
찍혀 있었고, 그 직후 "대상 사이트가 없습니다"가 떴다.

**원인**: `.github/workflows/auto_run.yml`이 `${{ inputs.keywords }}`,
`${{ inputs.target_orgs }}` 같은 한글 값을 실행 스크립트 텍스트 안에 직접
끼워 넣고 있었는데, 사무실 Windows PC의 PowerShell 5.1이 이 스크립트 파일을
읽을 때 한글을 UTF-8이 아니라 한글 윈도우 기본 인코딩(cp949)으로 잘못
해석해서 글자가 깨져버렸다. 그 결과 `main.py`에 도착한 target_orgs 값이
이미 깨진 문자열이라, 명부의 실제 발주처 이름과 하나도 매칭이 안 돼서
"대상 사이트가 없습니다"로 조용히 끝난 것이었다.

**해결**: 한글이 섞인 값(키워드/발주처명)을 스크립트 텍스트에 직접 끼워넣지
않고 `env:` 블록의 환경변수로 전달하도록 워크플로우를 고쳤다. 환경변수는
GitHub Actions 러너가 프로세스 환경 블록을 통해 직접 전달하므로, 스크립트
파일 자체의 인코딩 문제와 무관하게 항상 정상적으로 전달된다. 추가로
`PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8` 환경변수도 넣어서, 파이썬이
콘솔(실행 로그)에 한글을 출력할 때도 같은 인코딩 문제로 깨지지 않도록 했다.

**참고**: 이번에 `.github/workflows/auto_run.yml`을 처음부터 다시 정리하면서,
그동안 채팅으로 안내드렸던 파이썬 경로 고정(`C:\Program Files\Python311\python.exe`)과
구글 키 파일 BOM 방지(UTF8Encoding 직접 사용) 수정사항도 이 zip 안의 파일에
전부 반영해뒀다 - 그동안 이 파일은 채팅에서만 안내하고 zip에는 반영이 안 되어
있어서 서로 어긋나 있었다.

## "새 발주처 추가"가 드롭다운에 안 뜨는 버그 수정

**실제로 발견된 버그**: "➕ 새 발주처 추가"에서 발주처를 등록하면 `url_overrides`
구글시트에는 정상적으로 저장되는데, "공고 자동수집" 화면의 "타겟 발주처 설정"
드롭다운(`get_target_org_list()`)은 **등록명부 엑셀 파일만 읽고 있어서** 새로
추가한 발주처가 영원히 목록에 안 나타나는 문제가 있었다. 등록은 되는데 정작
그걸 선택해서 돌릴 방법이 없는, 앞뒤가 안 맞는 상황이었다.

이제 `get_target_org_list()`가 등록명부 엑셀 + `config.EXTRA_SITES` + `url_overrides`
시트(발주기관명 컬럼)를 모두 합쳐서 반환하도록 고쳤다. 또한 "새 발주처 추가"/
"URL 수정"/"오버라이드 삭제" 세 곳 모두에서 이 목록의 캐시를 즉시 비우도록
(`get_target_org_list.clear()`) 추가해서, 등록하자마자 새로고침 없이 바로
드롭다운에 나타난다 (기존에는 5분 캐시가 있어서 어차피 기다리면 나타나긴
했겠지만, 즉시 반영되는 게 훨씬 자연스럽다).

## 방위사업청(D2B) 전용 핸들러 신규 추가

방위사업청 국방전자조달시스템(`d2b.go.kr`)은 일반 HTML 게시판이 아니라, 브라우저
개발자도구 Network 탭으로 직접 확인한 결과 **POST로 JSON 데이터를 받아오는
방식**이었다 (`getServiceBidAnnounceListNew.json`). 게다가 기본 화면이 '개찰일자'
(입찰이 열리는 미래 날짜) 기준으로 정렬되고 전체 400건이 넘어서, 일반적인
'최신 등록순 페이지네이션 후 중지' 방식으로는 원하는 키워드가 있는 공고가 있어도
찾기 어려웠다 (실제로 "안전"이 들어간 공고가 7건 있었는데도 우리 로직으로는
0건이 나왔었음).

`scrapers/custom/d2b.py`를 새로 만들어서, 이 사이트 자체의 '입찰건명' 검색
기능을 그대로 활용하도록 했다 - 세션 쿠키를 먼저 받은 뒤, 우리가 찾는 키워드
각각으로 직접 검색해서 필요한 것만 가져온다. 응답 JSON의 `rpstItnm`(제목),
`anmtDate2`(공고일자), `codeVld3`(실제 발주부대명, 예: 제7보병사단·해군군수사령부
등)를 실제 캡처한 응답 예시로 재현 테스트했고, 핵심 키워드 강제포함/순수 제외
필터도 다른 사이트들과 동일하게 동작하는 것까지 확인했다. `config.py`의
`CUSTOM_HANDLER_DOMAINS`에 `"d2b.go.kr": "d2b"` 한 줄만 추가하면 `site_registry.py`가
자동으로 이 도메인을 전용 핸들러 대상으로 분류한다(별도 수정 불필요).

**한계**: 개별 공고로 바로 가는 직통 링크를 못 찾았다 (자바스크립트로 상세 팝업을
띄우는 방식으로 보임) - 상세링크는 일단 검색 목록 화면 자체로 채워둔다.

## "🗒️ 전수조사 로그 (AI 분석용)" 메뉴 신설

사용자 지적: "실패 로그에 안 뜨는 게 있을 수도 있잖아" - 맞는 말이었다. 기존
`run_log`(실패 로그)에는 `log_failure()`/`log_manual_required()`로 남긴 것만
쌓이고, **성공한 사이트는 하나도 기록되지 않았다** (`log_info()`로 콘솔에만
잠깐 찍히고 사라짐). 그래서 "전체 중 정확히 몇 곳이 어떤 방식으로 성공/실패
했는지" 종합적인 그림을 볼 방법이 없었다.

새 구글시트 탭 두 개를 추가했다:
- `site_results`: 성공/실패 관계없이 처리한 사이트마다 한 줄씩 (발주처, URL,
  처리방식(requests/selenium/custom 중 무엇이 먹혔는지), 결과, 수집건수,
  제외건수, 소요시간, 실패 시 사유)
- `run_summary`: 실행 1회당 요약 한 줄 (실행ID, 시작/종료시각, 총소요시간,
  실행위치(클라우드/사무실PC - `GITHUB_ACTIONS` 환경변수로 자동 판별), 이번
  설정(키워드/기간/발주처/프록시), 전체/성공/실패 수, 신규공고/자동제외 수)

두 시트는 `실행ID`(타임스탬프+임의문자열)로 서로 연결된다. `engine.py`의
`process_site()`가 이제 처리방식(`method_used`)과 소요시간(`elapsed_seconds`)도
함께 반환하도록 확장했고, `run_all_sites()`가 성공/실패 관계없이 사이트마다
결과를 모아 `site_results`로 반환한다. 실제 시나리오(사이트 1곳 성공)로
실행ID가 두 시트에 정확히 일치하게 저장되는 것까지 통합 테스트로 확인했다.

대시보드에는 "🗒️ 전수조사 로그 (AI 분석용)" 메뉴가 새로 생겨서, 실행을
골라 요약+사이트별 결과를 보고, 맨 아래에서 **AI에게 그대로 붙여넣을 수 있는
텍스트**(`st.code` 블록 - 복사 버튼 내장)를 바로 복사할 수 있다.

## "등록된 URL 목록"에서 바로 삭제하는 기능 추가

**실제로 발견된 문제**: "✏️ 등록된 발주처 수정" 탭의 삭제 기능은 드롭다운에서
발주처를 골라야 하는데, 그 드롭다운(`site_registry.get_org_default_url_map`)이
**등록명부 엑셀에 있는 것만** 보여준다. "나라장터", "한국수력원자력(주)"처럼
"➕ 새 발주처 추가"로만 등록되고 엑셀에는 없는 항목은 드롭다운 자체에 안 나타나서,
있는 삭제 기능으로는 지울 방법이 없었다 (드롭다운이 안 새 발주처 목록 병합 문제와
같은 유형의 버그).

"📋 현재 등록된 직통 URL 목록" 표 자체를 `st.data_editor`로 바꿔서, 각 행 앞에
체크박스를 추가했다. 체크한 항목들을 "🗑️ 선택한 항목 삭제" 버튼으로 한 번에
지울 수 있다 - 드롭다운을 거치지 않고 목록에 보이는 모든 항목(엑셀에 있든 없든)을
지울 수 있으므로 위 문제를 근본적으로 해결한다.

## 세종도시교통공사 = "조달청 이관"과 같은 케이스로 확인됨

실제 화면으로 확인: 세종도시교통공사 자체 사이트의 "입찰공고" 메뉴를 누르면
**나라장터로 그대로 리다이렉트**된다 - 자체 게시판이 아예 없는 구조다. 이건
기존에 알고 있던 "*24년부터 조달청*" 표시 기관들과 완전히 같은 상황(정상)인데,
발주처 이름에 "조달청"이라는 글자가 없어서 기존 판별 로직(`G2B_MIGRATION_HINT`
문자열 포함 여부)으로는 못 잡아내고 계속 "구조 문제(확인 필요)"로 헷갈리게
표시되고 있었다.

`config.KNOWN_G2B_REDIRECT_ORGS`라는 새 목록을 추가해서, 이름에 표시가 없어도
실제로 나라장터로 이관된 것으로 직접 확인한 발주처를 등록해두면 같은 "정상"
사유로 표시되도록 했다 (현재 세종도시교통공사 1건 등록). 실제 상황을 재현한
테스트와, 기존 "*24년부터 조달청*" 패턴이 회귀 없이 그대로 동작하는 것까지
확인했다. 앞으로 비슷한 사례(이름에 표시는 없지만 실제로는 나라장터 이관인 곳)를
발견하면 이 목록에 하나씩 추가하면 된다.

## `<a>` 태그 없이 onclick으로 여는 게시판 지원 (대전 동구청)

**실제로 발견된 문제**: 대전 동구청은 게시판 선택자로 행(6개)은 정상적으로
찾았는데("성공(0건)"으로 표시됨), 그 안의 진짜 공고("2026년 소규모 노후건축물
안전점검 대상 모집 공고" 등)를 전부 놓치고 있었다. 원인은 `extract_row_fields()`가
**행 안에 `<a>` 태그가 반드시 있어야만** 동작하도록 되어 있었기 때문 - 이
사이트는 `<tr onclick="...">`로 자바스크립트 상세보기를 여는 방식이라 애초에
`<a href>` 자체가 없는 행이었다.

`<a>` 태그가 없어도 제목은 그대로 셀 텍스트에서 뽑아내고(`_pick_title`이
앵커 없이도 동작하도록 일반화), 상세 링크만 게시판 목록 주소 자체로 대체하도록
고쳤다(개별 공고로 바로 가는 주소를 알 수 없기 때문 - 방위사업청과 같은 방식).
실제 화면 구조를 그대로 재현해 정확히 제목/날짜가 뽑히는 것과, 기존
사이트들(아산시·보령시)의 `<a>` 태그 있는 케이스는 회귀 없이 그대로 동작하는
것까지 확인했다.

## 날짜(범위) 텍스트가 제목으로 잘못 뽑히는 문제 방지 + 발주처별 원클릭 테스트 버튼

대전 동구청 재현 테스트: `<a>` 태그 수정 이후에도 여전히 0건이 나온다는 피드백을
받고 재점검한 결과, "게재기간"(예: "2026-08-21 ~ 2026-09-18") 같은 날짜 범위
텍스트가 실제 제목보다 길어지는 경우 `_pick_title()`이 날짜를 제목으로 잘못
골라버릴 수 있는 취약점을 발견했다. `_DATE_ONLY_PATTERN`을 추가해서, 순수하게
날짜/날짜범위로만 이루어진 텍스트는 `_NOTICE_NUMBER_PATTERN`과 마찬가지로 후보에서
제외하도록 했다. 제목이 6자, 날짜범위가 23자인 극단적인 경우까지 만들어서 정확히
제목이 뽑히는 것과, 유성구청처럼 제목 자체가 날짜로 시작하는 케이스(예: "2026.08.27
신규 공고 A")는 회귀 없이 그대로 동작하는 것까지 확인했다.

또한 "✏️ 등록된 발주처 수정" 탭에 **"🧪 지금 바로 이 발주처만 테스트"** 버튼을
추가했다. URL을 저장한 뒤 다른 메뉴로 이동하지 않고 그 자리에서 바로 그 발주처
하나만 빠르게(수집기간 60일 고정) 테스트하고 로그를 바로 볼 수 있다.

## 아이건설넷 로그인 로직 전면 재작성 (엉뚱한 검색창에 입력하던 버그)

실제 화면 캡처로 확인: 첫 화면에 "아이디 로그인"/"공동인증서 로그인" 두 탭이 있고
(공동인증서 로그인은 자동화 사실상 불가능하지만, 다행히 아이디/비밀번호 로그인도
지원함), 화면 맨 위에 "공고명을 검색하세요"라는 검색창도 있다. 예전 코드는
`document.querySelector('input[type="text"]')`처럼 "페이지에서 처음 보이는
텍스트 입력칸"을 무작정 골랐는데, DOM 순서상 그 검색창이 로그인 아이디 칸보다
먼저 나올 가능성이 높아 **아이디를 엉뚱하게 검색창에 입력하고 있었을 것으로
추정된다** - 그래서 로그인이 계속 조용히 실패했다.

`scrapers/custom/igunsul.py`를 다시 작성해서, placeholder 텍스트("아이디 입력",
"비밀번호 입력")로 정확한 칸만 콕 집어서 채우고, 첫 번째 `<form>`을 무작정
제출하는 대신 "로그인"이라는 글자가 있는 버튼/링크를 정확히 찾아서 클릭하도록
바꿨다. 검색창처럼 조건에 안 맞는 필드는 셀렉터 자체가 안 맞아서 절대 안 건드리게
된다. 로그인 입력~버튼 클릭까지 전체 흐름을 모킹으로 재현해 정확한 칸에 정확한
값이 들어가고 로그인 버튼이 정확히 클릭되는 것까지 확인했다.

## 아이건설넷 - 로그인 버튼 클릭이 팝업 오버레이에 막히는 문제 해결

이전 수정(placeholder 기반 정확한 칸 찾기) 배포 후 실제 로그로 확인: 아이디/
비밀번호 입력칸은 정확히 찾았고 로그인 버튼(`id="login_btn"`)도 정확히 찾아냈지만,
`ElementClickInterceptedException`으로 클릭이 실패하고 있었다 - 화면에 뜬 팝업/
배너의 반투명 오버레이(`<div id="blackPanel">`)가 그 버튼 위를 덮고 있어서
일반 클릭이 막힌 것이었다 (KHNP의 팝업 문제와 같은 종류).

일반 클릭이 실패하면 자바스크립트로 직접 클릭 이벤트를 발생시키도록
(`driver.execute_script("arguments[0].click();", login_btn)`) 폴백을 추가했다 -
이러면 화면상 다른 요소가 위에 덮여 있어도 상관없이 눌린다. 클릭 인터셉션
상황을 그대로 재현해 정상적으로 자바스크립트 클릭으로 넘어가고, 로그인 이후
실제 게시판 데이터까지 끝까지 파싱되는 것을 확인했다.

## 아이건설넷 - 로그인 방식을 "Enter 키" 우선으로 전면 교체

실제 로그로 확인: 이전 버튼 클릭 방식이 에러 없이 실행됐는데도 로그인 후 주소가
`https://www.igunsul.net/`(로그인 전 홈 화면) 그대로였다 - 찾아낸 "로그인" 버튼이
실은 상단 메뉴의 로그인 페이지 이동 링크였을 가능성이 높고(embedded 위젯의 진짜
제출 버튼이 아니었을 것으로 추정), 그래서 클릭은 됐지만 실제 인증은 안 됐던
것으로 보인다.

이제 아이디/비밀번호를 채운 뒤 **비밀번호 칸에서 Enter 키를 누르는 방식**을
1순위로 쓴다 - 어떤 버튼이 진짜 제출 버튼인지 헷갈릴 필요가 없어서 훨씬
안전하다. Enter로도 주소가 안 바뀌면 기존 버튼 클릭 방식을 보험으로 한 번 더
시도하고, 그래도 안 바뀌면 이제는 "로그인 시도 후에도 주소가 안 바뀜"이라는
명확한 사유로 실패 로그에 남긴다(예전에는 이런 구분 없이 그냥 "0건"으로만
남아서 원인 파악이 어려웠음). 3가지 시나리오(Enter로 성공 / 버튼으로 겨우 성공 /
둘 다 실패)를 모두 재현해 정확히 분기되는 것과, 성공 시 불필요한 버튼 검색
단계를 건너뛰는 것까지 확인했다.

## 아이건설넷 - 로그인 실패 시 화면 에러 문구까지 함께 진단

로그인이 계속 실패하는데 아이디/비밀번호 값 자체는 문제없어 보이는 상황이라,
"진짜 자격증명 문제인지" vs "봇 자동화를 감지해서 막는 건지"를 구분할 필요가
생겼다. 로그인 시도 후 주소가 안 바뀌면, 화면의 `<body>` 텍스트를 긁어서
"일치하지", "틀렸", "캡차", "자동입력방지", "로봇", "차단" 같은 단서 단어가
있는지 확인하고, 화면 상단 300자 스니펫과 함께 실패 로그에 남기도록 추가했다.
실제 "일치하지 않습니다" 문구가 있는 경우 정확히 잡아내는 것과, 특이 문구 없는
평범한 페이지에서는 "없음"으로 정확히 구분되어 오탐이 없는 것까지 확인했다.
다음 실행부터는 이 스니펫으로 정확한 원인(자격증명 문제 vs 봇 차단 vs 다른 문제)을
바로 알 수 있다.

## 그 외 알려진 이슈 / 참고사항

- **KHNP 셀렉터 검증 필요**: `scrapers/custom/khnp.py`는 화면 캡처 기반 추정으로
  작성됨. 실제 테스트에서도 `click_menu` 단계에서 실패가 확인됨(예상된 결과) -
  보안이 강한 사이트라 수동 확인 목록에 남기는 것을 권장. (한국수자원공사,
  인천국제공항공사도 비슷한 유형의 전용 입찰시스템으로 보임 - 나중에 여유 있을 때
  KHNP 고치는 김에 함께 검토)
- **일부 사이트는 클라우드 IP 자체를 차단함** (실제 테스트로 확인: 보령시청은
  `ConnectTimeout`으로 접속 자체가 안 됨 - 셀렉터 문제가 아니라 Streamlit Cloud의
  해외/클라우드 IP를 막고 있는 것으로 추정됨). 이런 사이트는 코드로 해결 불가하며,
  국내 IP를 경유하는 별도 인프라(국내 서버/프록시)가 필요함. `manual_check` 사유에
  "클라우드 IP" 문구가 있으면 이 케이스임.
- **iframe 안에 게시판이 있는 사이트 대응 추가됨**: 대전 동구청처럼 메뉴 페이지
  안에 실제 게시판이 다른 도메인의 iframe으로 끼워진 패턴을 실제 페이지 소스로
  확인하고 자동 탐지 로직을 추가함(`scrapers/base.py`의 `discover_additional_boards`).
- **나라장터(G2B) API 400 에러 수정**: 실제 실행 로그에서 `HTTP 400`을 확인 -
  공공데이터포털의 '인코딩' 서비스키를 그대로 넣으면 이중 인코딩되어 발생하는
  흔한 문제. `scrapers/api_g2b.py`에서 키를 한 번 디코딩해서 방어하도록 수정함.
  그래도 400이 계속 뜨면 `run_log`에 응답 본문 일부가 함께 남으므로 원인을 바로
  확인 가능.
- **등록명부 엑셀의 우측 블록**(19번째 열부터 발주처/모집공고일 등이 한 번 더
  반복되는 부분)은 URL 컬럼이 없어 현재 코드에서 수집 대상에 포함하지 않는다.
  이 블록의 기관들을 자동 수집 대상으로 삼아야 한다면 별도 URL 컬럼을 추가하거나
  `site_registry.py`의 로직을 확장해야 한다.
- **"*24년부터 조달청*" 표시 기관**: 실제 데이터로 확인한 결과 16곳 중 7곳은
  자체 게시판에서도 여전히 공고가 잡히고(한국환경공단, 한국농어촌공사 등),
  9곳은 자체 게시판에서 0건이 나옴. 후자는 `manual_check`에 "나라장터로 별도
  수집되고 있으니 실제 문제가 아닐 가능성이 높음"으로 구분 표시됨 - 정상 동작.
- **Selenium 동시 실행 수(`config.MAX_WORKERS_SELENIUM`)**: Streamlit Cloud
  무료 플랜은 메모리가 넉넉하지 않다. 자꾸 수집이 중간에 멈추면 이 값을 1로
  낮춰서 안정성을 우선하는 것을 고려.
